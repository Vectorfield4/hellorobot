# Товары WooCommerce

Каталог живёт в репозитории и заливается в WooCommerce скриптом без зависимостей. Смысл —
держать товары в тех же тегах, что и статьи: блок «Купить робота» под статьёй появляется
только когда хотя бы один тег статьи совпал с тегом товара.

Файлы: `products/catalog.json` (каталог), `scripts/products.mjs` (скрипт),
`test/productsScript.test.ts` (тесты), `src/shared/config/productTags.ts` (теги на фронте).

## Как завести товар

1. Добавьте объект в `products.products[]`. Обязательны `sku` (уникальный, вида
   `HR-UNITREE-G1`) и `name`; `slug` лучше задать руками.
2. `tags` — **имена тегов, которые уже есть в блоге** (`гуманоиды`, `коботы`,
   `манипуляторы`, `навигация`, …), 2–4 штуки. Новых тегов не выдумывайте: их не будет в
   статьях, и покрытия не появится. `categories` — как в примере (`Гуманоиды`,
   `Манипуляторы`); термины WooCommerce создаёт сам, id передавать не нужно.
3. Сухой прогон печатает payload и ничего не отправляет:

```bash
node scripts/products.mjs import --file products/catalog.json --dry-run
```

4. Без `--dry-run` тот же вызов делает upsert по `sku`: `GET /products?sku=…`, затем
   `POST /products` (новый) или `PUT /products/<id>` (существующий). `review_note`
   игнорируется — это заметка для человека. Товар без `sku`/`name` пропускается (код 1).

## Ключи WooCommerce

WooCommerce → Настройки → Дополнительно → REST API → «Добавить ключ», права **read/write**.
Дальше переменные окружения (PowerShell, на одну сессию):

```powershell
$env:HELLOROBOT_WP_URL = "https://hello-robot.ru"
$env:HELLOROBOT_WC_KEY = "ck_…"
$env:HELLOROBOT_WC_SECRET = "cs_…"
```

Без ключей работают `import --dry-run` и `list` через публичный Store API
(`/wp-json/wc/store/v1/products`). Пишущая команда без ключей печатает ошибку и выходит с
кодом **2** — это не баг, а незаполненное окружение.

## Воркфлоу после перевода статьи

```bash
node scripts/products.mjs ensure --slug <slug>
```

Скрипт берёт теги статьи в WordPress (`/wp/v2/posts?slug=…`, имена терминов — из
`/wp/v2/tags`), теги товаров — из Store API, и печатает таблицу «тег статьи → сколько
товаров с этим тегом». Коды выхода: **0** — хотя бы один тег покрыт и блок отрисуется;
**1** — покрытия нет, смотрите список непокрытых тегов; **2** — не смогла отработать (нет
сети, нет ключей, статья не найдена, у статьи нет тегов). Сообщение печатается без stack
trace.

Теги можно передать напрямую, не трогая статью; `--dry-run` у `ensure` не ходит в сеть и
считает покрытие по локальному `products/catalog.json`:

```bash
node scripts/products.mjs ensure --tags "гуманоиды,коботы" --dry-run
```

`--fix` добавляет недостающее: для каждого непокрытого тега находит товар в каталоге,
создаёт или обновляет его через WC REST и перепроверяет покрытие (без ключей — код 2):

```bash
node scripts/products.mjs ensure --slug <slug> --fix
node scripts/products.mjs list [--tag коботы]
```

## Алиасы тегов

`TAG_ALIASES` в `scripts/products.mjs` — карта «канонический русский тег → варианты
написания», добавить алиас = одна строка (`экзоскелеты: ["exoskeleton", "экзоскелет"]`).
Нормализация одна на всех: lowercase, `ё`→`е`, пунктуация и лишние пробелы убираются,
потом алиас сводится к канону. Ту же карту держит фронтенд
(`src/shared/config/productTags.ts`) — набор канонов должен совпадать, иначе `ensure`
скажет «покрыто», а блок под статьёй не появится.

## Почему draft

`import` всегда создаёт товар в `draft`, `--publish` публикует только то, что в файле явно
помечено `status: "publish"`, и не трогает чужие draft-товары. Магазин не показывает
позицию, пока человек не проверил:

- **цену** — `price`/`regular_price` строкой, `"0"` значит «цена неизвестна»;
- **наличие** — `stock_status: "onbackorder"`, где срок поставки не подтверждён;
- **картинку** — `images: [{ "src": "https://…" }]`, WooCommerce скачивает её сам;
- **описание** — 2–4 предложения без маркетингового шума.

Проверили — поставьте `status: "publish"` и повторите импорт с `--publish`. Пока товары в
draft, `ensure` и Store API их не видят: покрытия не будет.
