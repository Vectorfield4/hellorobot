# Товары магазина

Каталог живёт в репозитории (`products/catalog.json`) и заливается в WooCommerce
детерминированным деревом узлов из скил-репозитория. Задача одна: под статьёй про
роботов должен стоять робот, которого можно заказать.

## Три правила

1. **Тег функционален.** Товар попадает в каталог, только если у него есть тег,
   который уже используют статьи. Читатель открыл материал про гуманоидов —
   блок «Купить робота» покажет гуманоида. Тег назначается правилами
   (`products/tag-rules.yaml`), а не на глаз.
2. **Бренд внутренний.** `data/<host>/sellers.yaml` — allowlist брендов и
   продавцов. Он решает доверие, порядок в очереди и допуск к публикации.
   На сайте бренд не выводится, это наш сигнал качества.
3. **Цена не покидает `data/`.** Собранная с сайта бренда цена лежит в
   `data/<host>/prices.yaml` и нужна для звонка. В WooCommerce уходит
   `regular_price: "0"`, страница цену не показывает, JSON-LD `offers` нет.
   Это не публичная оферта: стоимость называем лично.

## Файлы

| Путь | Что это | В git |
|---|---|---|
| `products/catalog.json` | что продаём: sku, имя, теги, категории, картинка, статус | да |
| `products/tag-rules.yaml` | правила «модель → теги блога» | да |
| `docs/sellers.example.yaml` | стартовый allowlist брендов | да |
| `data/<host>/sellers.yaml` | рабочий allowlist | нет |
| `data/<host>/prices.yaml` | прайс-лист для звонка | нет |
| `data/<host>/index/<domain>.json` | индекс моделей бренда (JSON-LD) | нет |
| `data/<host>/audit.json` | матрица «тег статьи × товары», пробелы | нет |
| `data/<host>/runs/<stamp>/` | манифест и сводка прогона | нет |

`data/` целиком в `.gitignore`: там локальные данные и артефакты прогонов.
Скриптов в проекте нет — они живут в скилах
(`~/.config/opencode/skills/content/shop-*/scripts/`).

## Как это запускается

Команда `добавь товары` (`/add-products`) поднимает `content-shop-filler`, тот
идёт по дереву узлов. Каждый узел — отдельный скил с одной работой:

| # | Скил | Работа |
|---|---|---|
| 1 | `shop-write` capabilities | чем писать: WC REST (batch) или WordPress MCP (5 вызовов) |
| 2 | `shop-vendors` | allowlist брендов |
| 3 | `product-match` aliases | `productTags.ts` → `data/<host>/tag-aliases.json` |
| 4 | `shop-audit` | теги статей, товары включая draft, список пробелов |
| 5 | `shop-harvest` | sitemap + schema.org Product с сайтов брендов |
| 6 | `shop-price-ledger` | цены → `prices.yaml`, только локально |
| 7 | `shop-tagmap` | модель → канонические теги блога |
| 8 | `shop-plan` | пробелы × модели → очередь (gap, потом premium) |
| 9 | `shop-gate` | trust + unique + spec → publish или draft |
| 10 | `shop-catalog` | вердикты → `products/catalog.json`, идемпотентно |
| 11 | `shop-write` | отправка в WooCommerce выбранным транспортом |
| 12 | `shop-verify` | виден ли товар в Store API, легли ли теги |
| 13 | `shop-report` | манифест, метрики, сравнение с прошлым прогоном |

Вручную те же узлы запускаются по одному:

```bash
S="$env:USERPROFILE/.config/opencode/skills/content"
node "$S/shop-audit/scripts/audit.mjs"
node "$S/shop-harvest/scripts/harvest.mjs" --sellers data/hello-robot.ru/sellers.yaml
node "$S/shop-tagmap/scripts/tagmap.mjs" --rules products/tag-rules.yaml
node "$S/shop-plan/scripts/plan.mjs" --sellers data/hello-robot.ru/sellers.yaml
```

Коды выхода одинаковые у всех узлов: `0` — сделано, `1` — результат
«добавлять нечего / не всё видно», `2` — ошибка воркфлоу (нет файла, нет ключей,
битые флаги).

## Публикация

`publish` ставится, когда сходятся три вердикта:

- **trust** — бренд есть в `sellers.yaml`;
- **unique** — на сайте нет товара с таким sku, именем или двумя общими словами
  имени (`Unitree G1` и `Unitree G1 Pro` — один товар);
- **spec** — есть картинка и есть что показать: категория или описание.

Цена в гейте не участвует. Не прошедший товар остаётся `draft`, а причины
попадают в `review_note` — без упоминания цены.

## Русский текст карточки

Названия, короткие и полные описания живут в WooCommerce и в
`products/catalog.json` по-русски: общие слова переведены, бренд и модель
остаются латиницей. Выгрузка поставщика (`automated mobile robots,amr...`,
HTML-сущности вида `&#8212;`) в магазин не попадает. `shop-write` отправляет в
WooCommerce ровно то, что лежит в каталоге, поэтому каталог — единственное
место, где правится русский текст товара.

Тест `test/product.test.ts` проверяет каждый опубликованный товар каталога:
описание без HTML-сущностей и с кириллицей. Сайт дополнительно декодирует
числовые сущности из Store API (`plainText.ts`) — если в магазине появится
такой товар, на странице будет знак, а не код.

## Год выпуска

Год выпуска модели — локальный атрибут WooCommerce «Год выпуска» (`2024`).
Store API отдаёт его в `attributes`, страница показывает строку «Год выпуска:
2024» под тегами. Нет атрибута — нет строки: год не выдумывается. В
`products/catalog.json` его нет, потому что магазинное дерево не переносит
атрибуты; правится он в WooCommerce (или в `product-update` на транспорте `wp`).

## Как блок «Купить робота» выбирает товары

Блок стоит в статье и на странице тега. Совпадение — по канону тега
(`productTags.ts`), порядок считает `getRelatedProducts`
(`src/shared/data/products.ts`):

- **Редкий общий тег весит больше частого.** Вес тега — `log(1 + N / df)`, где
  `df` — сколько товаров каталога его несут. «Манипуляторы» стоят почти на всём
  каталоге и сами по себе ничего не различают; «инспекция» или «складская
  логистика» различают, поэтому материал про склад получает AMR, а не первый по
  алфавиту кобот.
- **Зерно статьи.** При равном весе порядок задаёт FNV-хеш от `slug статьи +
  sku`, а не имя товара. Сборка детерминирована (один и тот же slug даёт один и
  тот же срез), но два материала с похожими тегами больше не показывают один и
  тот же список: до правки 30 статей давали 22 разных набора, после — 29.
- **Три карточки в статье, пять на странице тега.** В статье блок — тизер, а не
  витрина: при шести гуманоидах в каталоге пять ячеек гарантировали повтор.
  Верхняя граница показов — `статей × слотов / товаров в классе`, поэтому
  разнообразие растёт не правкой порядка, а закрытием пробелов: на 25 октября
  2026 из 73 тегов статей 52 не имеют ни одного товара.

## Заказ

На странице товара нет цены. Слева галерея, справа имя, теги, год выпуска,
короткое описание и большая кнопка **«Заказать»** во всю ширину колонки. Полное
описание стоит ниже двух колонок. Кнопка открывает модальное окно с формой
(`OrderPanel`), а не раскрывает блок на странице; Escape и клик по фону
закрывают его, фокус возвращается на кнопку. Заявка уходит в
`POST /wp-json/hellorobot/v1/order` (mu-plugin в `wp/`), заказ создаётся в
статусе `on-hold`. Стоимость менеджер называет по телефону.

Поэтому `regular_price` в payload — всегда `"0"`: с пустой ценой WooCommerce
считает товар непокупаемым (`is_purchasable = false`) и форма заказа исчезает.

## Что не попадает в каталог

Индекс бренда — это всё, что нашлось на его сайте, включая аксессуары и
маркетинговые страницы. Магазину они не нужны, поэтому `shop-tagmap` отбрасывает
их до планирования:

- **аксессуар** — батарея, мотор, лидар, контроллер, кабель, модуль, док, кейс,
  плата, ПО, услуги, доставка (`ACCESSORY_KEYWORDS` в `lib/shop/tagmap.mjs`);
- **не распознан тип робота** — в имени, категории и описании нет ни одного
  признака гуманоида, четвероногого, кобота, манипулятора, AMR, экзоскелета,
  дрона или мягкого захвата. Исключение — явное правило `kind: model` в
  `products/tag-rules.yaml`;
- **не похоже на товар** — имя-URL, имя без букв, название страницы («Store»,
  «Pages Archive»), нет картинки (`isPlausibleProduct` в `lib/shop/harvest.mjs`).

Всё отброшенное лежит в `tagged-index.json` → `skipped[]` с причиной. Это не
ошибка, а ответ «это не робот».

## Что реально отдаёт harvest

Индекс собирается из `sitemap.xml` и `schema.org Product` (JSON-LD), а если его
нет — из OpenGraph-меты со обязательным `og:type=product` **и** ценой/наличием.
Практика на hello-robot.ru:

| Бренд | Моделей | Источник |
|---|---|---|
| Unitree | 32 | JSON-LD на `shop.unitree.com` |
| Devonics | 74 | JSON-LD на Wix-магазине |
| Autel Robotics | 64 | JSON-LD на `shop.autelrobotics.com`, категория `drone` |
| Yarbo | 60 | JSON-LD на `www.yarbo.com` |
| Blue Robotics | 59 | только аксессуары: у самих ROV нет товарной разметки |
| Elephant Robotics | 27 | JSON-LD на `shop.elephantrobotics.com` |
| Robotemi | 22 | аксессуары temi; сам робот без цены |
| Beatbot | 20 | JSON-LD, категория `Robot` |
| Deep Trekker | 6 | JSON-LD; цены ROV не публикуются |
| QYSEA | 1 | FIFISH V-EVO, цена только по запросу |
| KEYi Tech | 2 | Loona Deskmate и Petbot |
| Mammotion | 2 | только SPINO (робот для бассейна), LUBA в sitemap нет |
| Pollen Robotics | 2 | JSON-LD/OG |
| Mobile Industrial Robots, Franka, Boston Dynamics, KUKA, Universal Robots | 0 | маркетинговый сайт без товарной разметки |
| DJI (`store.dji.com`), Hypershell, DNSYS, RobotShop | 0 | нет JSON-LD / 403 WAF / только Shopify-каталог без sitemap |

Ноль — честный результат: у этих брендов нет машиночитаемых товарных страниц,
цену и картинку придётся добавить руками. Повторный прогон не ходит в сеть, пока
индекс моложе `--ttl-days` (7 дней по умолчанию).

ROV как закрытие пробела.


## Прогон 1 → прогон 2

`content-shop-filler` пишет манифест каждого узла через
`shop-report/scripts/manifest.mjs` и `measure.mjs` (время и число HTTP-запросов
считает обёртка, а не сам узел). Замер на этом проекте:

| | прогон 1 (холодный индекс) | прогон 2 (тёплый) |
|---|---|---|
| времени | 28 158 ms | 10 822 ms |
| запросов | 49 | 5 |
| harvest | 2 бренда, 22 запроса | 0 запросов, индекс свежий |
| `merge --check` | — | 0 изменений |
| каталог | 18 товаров | байт-в-байт тот же |

Артефакты: `data/<host>/runs/<stamp>/manifest.json` и `summary.json`.

## Как завести новый бренд

1. `node "$S/shop-vendors/scripts/vendors.mjs" add --name "Unitree" --domain unitree.com --flagship "H1, G1"`
2. Если у бренда нет правила тегования, `shop-tagmap` покажет модель в
   `unmapped`. Добавьте строку в `products/tag-rules.yaml`:

```yaml
  - kind: brand
    match: Unitree
    tags: "роботы"
```

3. Повторите прогон. Индекс бренда кэшируется на 7 дней
   (`--ttl-days`), так что повторный запуск не пойдёт в сеть.

## Ключи WooCommerce

Нужны для транспорта `rest` и для чтения черновиков:

```powershell
$env:HELLOROBOT_WP_URL = "https://hello-robot.ru"
$env:HELLOROBOT_WC_KEY = "ck_…"
$env:HELLOROBOT_WC_SECRET = "cs_…"
```

Без ключей работает транспорт `wp` (WordPress MCP): `product-create`, две
`assign-cpt-terms` (`product_tag`, `product_cat`), `upload-image`,
`product-update`. `product-create` не умеет теги и картинки, поэтому «создать и
опубликовать» — это пять вызовов, а не один.

Публичный Store API показывает только `publish`, поэтому «товаров нет» при
двенадцати черновиках — не пустой магазин, а невидимые черновики. Аудит читает
WC REST со `status=any` именно поэтому.

## Проверка

```bash
node "$S/shop-verify/scripts/verify.mjs" store    --gated data/hello-robot.ru/gated.json
node "$S/shop-verify/scripts/verify.mjs" coverage --audit data/hello-robot.ru/audit.json
node "$S/shop-report/scripts/report.mjs" --run data/hello-robot.ru/runs/<stamp> --catalog products/catalog.json
```

`merge.mjs --check` на неизменных входах обязан выходить с кодом `0`: повторный
прогон не меняет каталог ни на байт.
